# 👾 Enemigos — design review and the enemy library (web tab + `docs/enemigos/`)

The web tab where enemy designs generated by a task are reviewed, and the library of enemies they become.
Plan and phases: `docs/tareas/enemigos-web.md`. Server-only: it goes through `tools/taller-server`
(`start.cmd`, http://localhost:3000); served any other way the tab says so.

## Files (all in the repo, so Claude reads and writes them directly)

| Path | What |
|---|---|
| `docs/enemigos/lotes/<id>.json` | a **batch** of designs one task generated. `{ title, request, createdAt, taskId?, items: [{ id, name, image, note?, status }] }`. `image` = `comfy:<path under Comfy's output>` (e.g. `comfy:claude/base_x_raw_00001_.png`) or a path under `docs/enemigos/`. `status` = `pending` / `accepted` / `discarded`. `name` = the proposed PascalCase name (the user can change it before accepting). |
| `docs/enemigos/<Name>/enemigo.json` | an **enemy** in the library: `{ name, estado, diseno: { image, source, lote, item, request, note }, pendientes: [], createdAt }` |
| `docs/enemigos/<Name>/diseno.png` | its design, copied out of Comfy's output (not in the repo) on accept |

`estado`: `por-montar` (design approved, make-enemy not run) → `montando` → `por-aprobar` (built, the user
tests it) → `aprobado` · `con-pendientes` · `descartado`. Phase 1 only writes `por-montar`.

**A design task must end by writing a batch file** (one per task, `<date>-<slug>.json`, items `pending`) —
that is how its results reach the gallery. Two demo batches (`demo: true`) are made from older Comfy bases.

## Server (`tools/taller-server/enemigos.mjs`, routes in `server.mjs`)

- `GET /api/enemigos` → `{ lotes, enemigos }`, read from disk on every call (Claude's edits show up with no watcher).
- `GET /api/img?src=…` → the image; only Comfy's output (`config.json → comfyOutput`, default
  `%LOCALAPPDATA%/Comfy-Desktop/ComfyUI-Shared/output`) and `docs/enemigos/`.
- `POST /api/enemigos/review { loteId, itemIds, decision: accept|discard|pending, names }` → `{ errors }` per item.
  Accept checks the name (PascalCase), that `docs/enemigos/<Name>` does not exist and that no
  `Assets/Prefabs/Enemies/**/<Name>.prefab` / `Enemy_<Name>.prefab` exists, then copies the design and writes
  `enemigo.json`. `pending` undoes either decision; undoing an accept deletes the enemy folder, refused once
  its `estado` is past `por-montar`.

## Web (`modules/enemies-panel.js`, markup `#tab-enemies`, styles `/* 👾 Enemigos */`)

Sections: **Diseños por revisar** (one foldable group per batch with pending items), **Biblioteca de enemigos**
(foldable by `estado`), **Lotes revisados** (folded). Card click = select; group bar = accept/discard the
selection or all that are left; ⤢ = viewer (← → move, A accept, D discard, Esc). Polls every 5 s while the tab
is visible; never re-renders while you type a name. Folded groups are remembered per browser tab
(`sessionStorage`).
